# AI 巡检四轮迭代完整测试用例

## 验收范围

覆盖自动调度、AI 服务派发、安全回调、计划策略、异常工作流、站内信、
统计运维、数据库迁移及 UniApp 多端构建。

## P0 阻断用例

| 编号 | 模块 | 测试场景 | 预期结果 |
|---|---|---|---|
| SCH-01 | 调度 | 到期且位于执行时间窗的计划 | 仅创建一个任务并派发 AI 服务 |
| SCH-02 | 调度 | 不在星期或时间窗内 | 不创建任务 |
| SCH-03 | 并发 | 两个实例同时调度同一计划 | 仅一个实例获得锁并创建任务 |
| SCH-04 | 锁恢复 | 实例异常退出且锁超时 | 其他实例可继续调度 |
| AI-01 | 派发 | AI 服务返回 2xx | 任务变为 `WAITING_AI` |
| AI-02 | 重试 | AI 服务超时后恢复 | 按配置重试并最终成功 |
| AI-03 | 失败 | 超过最大重试次数 | 任务变为 `FAILED`，记录次数和错误 |
| CB-01 | 回调安全 | 合法时间戳、随机数和 HMAC 签名 | 接收结果 |
| CB-02 | 回调安全 | 签名错误 | 返回 401，不写入结果 |
| CB-03 | 防重放 | 时间戳超出允许窗口 | 返回 401 |
| CB-04 | 防重放 | 相同随机数重复请求 | 第二次返回冲突，不重复写入 |
| CB-05 | 幂等 | 不同请求重复提交同一 `callbackId` | 返回同一结果，不重复写入 |
| DB-01 | MySQL | 执行基础及增量脚本 | 字段、索引和唯一约束完整 |
| DB-02 | PostgreSQL | 执行对应增量脚本 | 结构与 MySQL 业务字段一致 |
| DB-03 | Kingbase | 执行对应增量脚本 | 结构与 PostgreSQL 兼容 |
| FLOW-01 | 闭环 | AI 回调→复核→告警→站内信→处置 | 状态和未读数全链路同步 |
| BUILD-01 | 后端 | Java 8 执行 `mvn test package` | 自动化测试和打包成功 |
| BUILD-02 | H5 | 类型检查和 H5 构建 | 无错误并生成产物 |
| BUILD-03 | 微信小程序 | mp-weixin 构建 | 生成可导入产物 |

## 自动化覆盖映射

- 单元测试：计划校验、时间窗、回调幂等、异常合并、并发认领、健康状态。
- 集成测试：分布式锁、AI 重试、HMAC、防重放、数据库 CRUD 和关联清理。
- 浏览器测试：H5 登录、计划、异常、消息、告警详情和连续滚动。
- 构建测试：Java 8 JAR、H5、微信小程序。
- 人工/设备测试：Android、iOS、微信真机和生产网络策略。

## 通过标准

1. 所有 P0 必须通过。
2. P1 不允许存在数据重复、越权、孤立告警或孤立站内信。
3. 无法在本机执行的真机或跨数据库用例必须明确标为环境阻断。
4. 每个修复批次通过对应门禁后独立提交并推送。
