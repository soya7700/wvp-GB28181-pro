# WVP Mobile 与 AI 巡检版本测试用例

## 测试目标

验证当前分支能否完成编译、启动及核心业务闭环，并识别部署前的外部依赖、数据库迁移和配置风险。

## 测试环境

- 后端：Java 8、Maven、Spring Boot
- 移动端：Node.js、UniApp、Vue 3
- 首要目标：移动端 H5
- 扩展目标：微信小程序编译
- 后端依赖：MySQL、Redis、ZLMediaKit

## 测试用例

| 编号 | 级别 | 模块 | 测试步骤 | 预期结果 |
|---|---|---|---|---|
| BUILD-01 | P0 | 后端 | 使用 Java 8 执行 Maven clean/test/package | 编译及自动化测试通过，生成可运行 JAR |
| BUILD-02 | P0 | H5 | 执行 TypeScript 类型检查和 H5 构建 | 无类型错误，生成 H5 产物 |
| BUILD-03 | P1 | 微信小程序 | 执行 mp-weixin 构建 | 生成微信小程序产物 |
| BUILD-04 | P0 | Git | 执行差异格式及工作区检查 | 无空白错误，用户配置未被测试覆盖 |

| DB-02 | P1 | PostgreSQL/Kingbase | 校验对应建表脚本结构 | 与 MySQL 业务字段一致 |

| MODEL-01 | P0 | 模型 | 新增模型版本并激活 | 同一时间只有一个 `ACTIVE` 模型 |
| RULE-01 | P0 | 规则 | 创建带区域点位和阈值的入侵规则 | 规则保存并可查询 |
| RULE-02 | P1 | 阈值校验 | 创建阈值小于 0 或大于 1 的规则 | 返回参数错误 |
| EFFECT-01 | P1 | 效果统计 | 查询检测效果 | 按检测类型返回确认率与误报数量 |
| COMPAT-01 | P1 | 空数据 | 新数据库无计划、结果、模型时打开所有页面 | 显示空状态，不崩溃 |
| ERROR-01 | P1 | 外部依赖 | AI 服务未配置时打开巡检中心 | 显示“待配置”，基础平台仍可使用 |

## 通过标准

- 所有 P0 构建测试必须通过。
- 运行类 P0 用例如果因 MySQL、Redis、ZLMediaKit 或 AI 推理服务缺失无法执行，必须标记为“环境阻断”，不能标记为通过。
- 不允许出现数据重复、越权访问、重复告警、页面崩溃或滚动锁死。
- P1 失败不阻断开发环境启动，但必须形成修复清单。
